Method

  1. Cleaning. Prices such as “1.2 Crore” and road widths such as “30.00 ft” are parsed. Rows with impossible values are dropped, with the reason recorded. Unparseable optional fields are left missing, not guessed. {{ quality.raw_rows }} rows became {{ quality.clean_rows }}.
  2. Grouping. Listings with the same price and area are treated as one plot ({{ quality.cross_posted_groups }} plots were cross-posted under several localities). Folds and the test split never separate a plot's copies, which would inflate accuracy.
  3. Test split first. 20% of plot groups were set aside before any model was compared. They are scored only on request, and every scoring is logged.
  4. Model comparison. Two baselines, the original linear model, ridge regression and a random forest were compared by repeated grouped cross-validation. The regression and forest models predict log price per sq yd.
  5. Range. The {{ level }}% range is taken from the spread of out-of-fold errors. It is not a guarantee: it describes how wrong past estimates were.

Limitations

  • Only {{ bundle.metadata.rows }} listings from one snapshot of one website. Asking prices are not transaction prices.
  • Nothing about legal status (HMDA/DTCP approval, title, encumbrances), exact location, or amenities is in the data, and these move real prices a lot.
  • Plots larger than {{ bundle.schema.area_sqyd.p95|num }} sq yd or smaller than {{ bundle.schema.area_sqyd.p05|num }} sq yd are rare in the data, so estimates for them are rough.

What changed from the original project

  • The original prediction script passed land_area, no_of_open_gates and road_width to a model trained on Plot_Area, open_sides and Width_road. The mismatched columns were silently filled with zero, so every plot of the same facing got the same price: a negative number, hidden by abs(). Training and prediction now share one feature function, and the API rejects unknown fields.
  • The original model one-hot encoded listing titles and locations: 67 features for 47 training rows. It was scored on a single random split that ignored cross-posted duplicates.
  • Listings with any missing field were dropped (60 of 100 kept). Missing optional fields are now imputed ({{ quality.clean_rows }} kept).
